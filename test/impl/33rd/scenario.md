# 시험 시나리오 / Test Scenario — impl 33rd (Epic 33 공정성·시스템 카드, P2)
- 근거: 화면설계 SCR-N06(공정성·윤리 지표 `/compliance/fairness`)·N07(시스템·모델 카드 `/compliance/cards`). PRD FR-D10-05(공정성 지표 정례 측정·집단별 성능 분해·영향 평가 문서화)·FR-D10-06(카드 자동 생성·변경 시 갱신 강제·이해관계자 공개).
- 방식: 집단 = 요청 `subject.groups`(가명 범주 라벨, 키·값 모양·개수 제한) + 문자 체계(script → lang 축 기본값)를 판정 기록 모양에만 남김(원문·개인 식별 없음), 판정 기록에 보호 대상(target). 측정 = 보호 대상·기간의 집단별 차단율 + 레드팀 코퍼스 집단별 오탐·미탐을 d10-05(1.1.0, `block-rate-gap` %p 한도 `maxGapPp`)로 판정 → 원장 `fairness`·추세, 한도 초과 = 위험 등록부(열린 같은 출처 재사용). 영향 평가 = 원장 `impact_assessment`(없음·180일·이후 초과 = 갱신 필요). 카드 = 보호 대상(시스템)·모델 점검 대상 메타데이터 → ko·en 7 섹션, 입력 지문(목적·모델·데이터셋·프로파일·정책) 변경 = 갱신 필요 → D10-06 stale-card(거버넌스 스냅샷)·배포 게이트 차단, 공개 = 검토 요청 → 승인(`card_publish`) → 원장 `card`(판 덮어쓰기 없음). worker 주 1회 정례 측정(`FAIRNESS_INTERVAL_SEC`).
- 환경: local compose + 헤드리스 Chromium · garam.comp(garam, 규제 대응 — 시험 중 생성) · eng.kim · appr.one
